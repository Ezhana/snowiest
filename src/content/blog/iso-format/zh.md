## 一、常用格式（按精度）

| 精度              | 格式                        | 示例                        |
| ----------------- | --------------------------- | --------------------------- |
| 日期              | `YYYY-MM-DD`                | `2026-11-17`                |
| 日期+时间（到分） | `YYYY-MM-DDTHH:mm`          | `2026-11-17T14:30`          |
| 日期+时间（到秒） | `YYYY-MM-DDTHH:mm:ss`       | `2026-11-17T14:30:00`       |
| 带毫秒            | `YYYY-MM-DDTHH:mm:ss.sss`   | `2026-11-17T14:30:00.123`   |
| 带时区（UTC）     | `YYYY-MM-DDTHH:mm:ssZ`      | `2026-11-17T06:30:00Z`      |
| 带时区偏移        | `YYYY-MM-DDTHH:mm:ss±HH:mm` | `2026-11-17T14:30:00+08:00` |

## 二、关键规则

1. **日期与时间用 `T` 分隔**：`2026-11-17T14:30:00`（`T` 是标准分隔符，不能省略成空格——虽然很多系统宽容接受空格）。
2. **`Z` 表示 UTC**（零时区），等价于 `+00:00`。
3. **时区偏移写法**：`+08:00` 表示东八区（北京时间），`-05:00` 表示西五区。
4. **毫秒用小数点**：`.123`，最多可到微秒 `.123456`。
5. **周日期格式**（少用）：`2026-W47-2` 表示 2026 年第 47 周的周二。

## 三、常见示例

```text
2026-11-17                          # 纯日期
2026-11-17T14:30:00                 # 本地时间（无时区，有歧义，不推荐跨系统传输）
2026-11-17T14:30:00+08:00           # 北京时间
2026-11-17T06:30:00Z                # 同一时刻的 UTC 表示
2026-11-17T14:30:00.500+08:00       # 带毫秒
```

## 四、各语言生成方式

```javascript
// JavaScript
new Date().toISOString() // "2026-11-17T06:30:00.000Z"（总是 UTC）
```

```python
# Python
from datetime import datetime, timezone
datetime.now(timezone.utc).isoformat()   # "2026-11-17T06:30:00.123456+00:00"
```

```bash
# Shell / Linux
date -u +"%Y-%m-%dT%H:%M:%SZ"       # "2026-11-17T06:30:00Z"
date +"%Y-%m-%dT%H:%M:%S%:z"        # "2026-11-17T14:30:00+08:00"
```

## 五、建议

- **跨系统/存数据库/API 传输**：优先用带时区的格式，推荐 **UTC + `Z`**：`2026-11-17T06:30:00Z`，避免时区歧义。
- **只展示给人看**：`2026-11-17T14:30:00+08:00` 更直观。
- **避免**不带时区的 `2026-11-17T14:30:00` 用于存储或传输，因为无法判断是哪个时区。
