短页面最容易被一种“看起来更完整”的布局骗过去：页脚永远贴着视口底部，页面再短也填满一屏。但在长屏幕上，这种完整感会反过来伤害阅读。

## 现象

本站的关于页只有几百字。在 3000px 高的视口里打开它，正文结束后，页脚并不在正文后面，而是出现在屏幕最底部，中间隔着上千像素的纯背景色。读者顺着文章读到底，视线要穿过一大段空白，才能看到版权和友链。

这段空白既不属于正文，也不属于页脚，它只是被 flex 分配剩下的空间。

## 问题不在 min-h-screen

我一开始把账算在 `min-h-screen`（或 `min-h-full`）头上，但布局其实是三件事配合出来的：

```css
body {
  display: flex;
  flex-direction: column;
  min-height: 100dvh;
}
```

```html
<div class="flex-1"><slot /></div>
<footer class="mt-auto">…</footer>
```

`min-height` 提供一屏的高度，`flex-1` 把剩余高度全部给内容层，`mt-auto` 再把页脚推到最底。三件缺一不可，`min-h-screen` 只是这套 sticky footer 里最显眼的名字。

也就是说，只要页面把“剩余高度”分给了内容区，页脚就一定会远离正文，和用哪个类名无关。

## 两个走不通的方向

**直接去掉 min-height。** 页脚会紧贴正文，但页面高度只剩内容高度，视口下半部分改由 `html` 的背景绘制。`body` 上有 300ms 的 `background-color` 过渡，`html` 上没有；切换深浅色时，内容区在渐变，下方瞬间跳色，中间会出现一条看得见的分界。为了布局改出一个主题闪烁，不划算。

**保留 min-height，把空白塞进 main。** 给 `main` 加 `flex-1` 或 `min-h`，只是把空白从页脚上方挪到内容里边。页脚的位置没变，问题没变，还多了一个空的容器。

## 改法：把空白留在文档末尾

最后拆掉了整套 sticky footer 脚手架：

```css
body {
  /* 只为背景和主题渐变铺满视口，不再撑开布局 */
  min-height: 100dvh;
  margin: 0;
}
```

```html
<div class="animate-fade-up motion-reduce:animate-none"><slot /></div>
<footer>…</footer>
```

- `body` 回到普通块级流，去掉 `display: flex` 和 `flex-direction`；
- 内容包装层去掉 `flex-1`，保留出场动画；
- 页脚去掉 `mt-auto`。

页面于是变成：正文结束，页脚跟上，剩余高度是背景色。长页面本来就没有多余高度，完全不受影响；短页面则让页脚和最后一行正文待在同一屏里。改完在 3000px 高的视口里截图，页脚从屏幕底部回到了正文后面。

## 留白为什么应该留在页脚之后

纸质书的正文不会为了填满版心，把页码拉到页底。留白本身就是一个结束信号：读者看到正文结束，就知道这一页读完了。把页脚钉在视口底部，等于把“内容结束”和“页面结束”拆成两个位置，中间那段空白只能靠滚动跨过去。

如果确实需要页脚始终贴底，更好的做法不是撑开容器，而是在内容不足时主动设计一个结束区——签名、订阅入口、相关阅读——让那段空间有东西可放。空着，也比用 flex 撑开更诚实。

## 检查清单

- 页脚是内容的延续，还是视口的装饰？
- 空白出现在正文之后，还是被塞进了内容里面？
- 短页面时，背景过渡是否仍然覆盖整屏？
- 去掉撑高之后，还有哪些样式依赖那层 `flex-1`？

留白不是没排完的页面。把页脚放回它该在的位置，空白就只是空白。
